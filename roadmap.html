Why each phase must come first

Crawl

Maersk could not digitize customer experiences or run predictive models on data that did not yet exist in usable form. In 2017 the company still ran largely on paper, with up to 30 parties exchanging up to 200 communications per container (Dagar et al., 2024). Appointing a dedicated CIO (Logan, 2021), digitizing and standardizing shipping documents (Vlacic, 2022) and resolving the five key challenges of connecting supply-chain data (Rios, 2021) built the structured foundation that every later tool must read, trust and act on, so Walk cannot start before it.

Walk

Once data was digitized and standardized, Maersk could show it to customers and employees without manual translation between formats. Real-time ordering, invoicing and tracking became possible only because documents were already digital and consistent across parties. Port automation at Rotterdam (Petersen, 2015), Maersk Flow (Maersk, 2021) and Captain Peter (Maersk, 2019) turn Crawl data into usable experiences, but none yet produced the long sensor and behavioral histories that predictive and ecosystem systems need. That is why Run must follow Walk, not precede it.

Run

AI prediction and ecosystem platforms need a running history of real operational data. The Logistics Hub’s arrival predictions (Maersk, 2026) train on GPS and voyage data that exists only because Walk-phase tracking was already running; predictive maintenance and digital twins likewise need sensor histories. TradeLens (IBM, 2018) assumed the data standards built in Crawl would be adopted industry-wide, a dependency never fully met and a key reason it was discontinued in 2022 (TradeLens, 2022). It shows what happens when Run launches before its prerequisite exists ecosystem-wide.
